# Bootstrap App Themes from local state

App Themes will apply the browser's last-known Effective Theme before paint and reconcile it with the account after session loading. We accept a brief Default Theme on a new or cleared browser because resolving account and entitlement data in the root render would add request-time work and complicate the cached static shell, while a theme-neutral fullscreen loader would turn an occasional cosmetic transition into guaranteed blocking UI. A transient reconciliation failure retains the last-known theme; only an explicit ineligible or invalid response falls back to the Default Theme. Anonymous visitors always use Default, and signing out clears the local theme immediately so a private account preference does not carry into a shared browser's next session.
